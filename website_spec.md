# Ocean Website Spec

## Goal

Position Ocean as the trust and control layer for coding agents, with a homepage that feels technical, premium, operational, and visually distinct.

Reference palette direction: supermemory.ai uses a near-black base, sharp white typography, electric cyan/blue accents, mono technical labels, and catalog-like product surfaces.

## Core Message

Headline:

> Control coding agents before they touch production.

Subheadline:

> Ocean gives software teams a trust layer for AI coding: isolated agent workspaces, project-level spend control, validation evidence, and safe merges.

One-line positioning:

> The control plane for agentic development.

## Target Buyer

Primary:

- Software studio founders
- Engineering leads
- Service companies using multiple AI tools
- Teams managing AI spend and delivery risk

Secondary:

- Power developers running multiple agents locally
- AI-forward product teams

## Creative Concept

The website should not feel like a generic SaaS page. It should feel like an agent control room.

Visual metaphor:

> Multiple coding agents are moving fast through isolated lanes. Ocean sits above them as the control tower: budget, validation, risk, merge, audit.

The hero should show this directly:

- Live agent lanes
- Spend meter
- Validation gates
- Merge recommendation
- Risk state
- Human approval checkpoint

## Visual Direction

Use:

- Near-black background
- Electric cyan / blue primary accents
- White typography
- Mono labels like `LANE A`, `VALIDATION`, `MERGE HOLD`
- Thin borders
- Technical panels
- Data trails, scanlines, graph-like paths
- Real product UI artifacts, not abstract blobs

Avoid:

- Generic dashboard cards only
- Gradients as the main personality
- Purple-heavy AI startup look
- Stock illustrations
- "10x productivity" cliches
- Too much terminal-only framing

## Homepage Structure

### 1. Hero

- Headline
- Subheadline
- CTA: Download for macOS
- Secondary CTA: See team controls
- Hero visual: animated trust control room

### 2. Trust Flow

Four stages:

- Intake: agent receives scoped task
- Isolate: separate workspace lane
- Validate: tests, typecheck, security, spend
- Merge: human-approved PR

### 3. Software Studio Pain

Section headline:

> Protect project margins when every team uses AI.

Show:

- Project budget
- AI spend by developer / agent / project
- Productive output %
- Blocked sessions
- Risky diffs

### 4. Product Evidence

Show Ocean as a native workbench:

- Parallel lanes
- Session DAG
- Conflict detection
- PR checks
- Merge readiness
- Agent audit trail

### 5. Who It Serves

- Developers: run more agents safely
- Teams: govern AI adoption
- Studios: protect delivery margins

### 6. CTA

> Let agents move fast. Keep the repo under control.

## Signature Interactions

These would make the site feel unique:

- Hero ticker showing live trust events: `LANE B tests failing`, `BUDGET 56% used`, `SECURITY review required`
- Clickable dashboard tabs: Spend / Validation / Merge
- Agent lane animation: agents move from task to isolated workspace to validation to merge
- Hover states reveal evidence: "Why blocked?", "What changed?", "Cost of this session"
- Product proof panel that feels like an internal engineering tool, not marketing art

## Open Questions

1. Should the site optimize for download now or book demo / team sales?
2. Is the ICP more software studios in India/Asia or global engineering teams?
3. Do we want to show pricing on homepage, or keep it as "free during beta"?
4. Should Ocean look more like a developer tool or more like an enterprise control plane?
5. Can we use real Ocean screenshots, or should we build stylized product UI mockups?
6. Do we want the website to mention Claude/Codex/Cursor/Gemini directly?
7. What is the strongest proof we have today: tests, users, demos, architecture, or founder story?
